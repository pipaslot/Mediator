## Analýza

1. **Referenční vzory jsou hotové a ověřené.** `PIPMED001` (`CatchAllMiddlewareAnalyzer.cs`) demonstruje čistě
   syntaktický vzorec: symbol lookup jednou v `RegisterCompilationStartAction` (bail-out, pokud typ chybí),
   `SyntaxNodeAction` na konkrétní syntaxi, centrální `DiagnosticDescriptors.cs`, dogfooding přes
   `ProjectReference OutputItemType="Analyzer"` v `Pipaslot.Mediator.csproj`, balení do `analyzers/dotnet/cs`
   (beze změny pro nová pravidla — balí se celé `.dll`), release tracking v `AnalyzerReleases.Unshipped.md`,
   testy s named markup (`{|#0:...|}` + `.WithLocation(0)`). `PIPMED003`
   (`HandlerAuthorizationTypeMismatchAnalyzer.cs`) k tomu přidává druhý referenční vzor — sémantickou analýzu
   nad `INamedTypeSymbol.AllInterfaces` a kovariancí (`Compilation.ClassifyConversion`), se sdíleným helperem
   `HandlerActionTypes.cs` pro "jaké akce handler obsluhuje". `PIPMED005`
   (`MixedAuthorizationMechanismAnalyzer.cs`) staví na stejném helperu a přidává třetí opakovaně použitelný
   kousek — zjištění, jestli typ nese atribut implementující `IPolicy` (na typu samotném, jeho bázových
   třídách i implementovaných rozhraních), viz `GetPolicyAttributeNames`. `PIPMED004` níže na druhý vzor
   (`AllInterfaces`/`HandlerActionTypes`) přímo navazuje. Skill `roslyn-analyzers` popisuje všechny nástrahy (verzování `Microsoft.CodeAnalysis.CSharp`
   mezi analyzer a test projektem, corelib mismatch při `ProjectReference` na `Pipaslot.Mediator`, XUnit
   testing balíčky) — implementátor každé jednotky si ho má přečíst první.
   - Aktuální pin verze: `Microsoft.CodeAnalysis.CSharp` (analyzer projekt) a
     `Microsoft.CodeAnalysis.CSharp.Workspaces` (test projekt) = **5.6.0**, `ReferenceAssemblies.Net.Net80` +
     `ProjectReference ... SetTargetFramework="TargetFramework=net8.0"` na `Pipaslot.Mediator.csproj` v
     `tests/Pipaslot.Mediator.Analyzers.Tests.csproj`. Nová pravidla tuhle konfiguraci nemění.

2. **Kandidát "přímé volání `handler.Handle(...)` mimo mediator" byl zamítnut** — takové volání je typicky
   záměrné rozhodnutí konzumenta (izolovaný test handleru, řešení konkrétního problému), ne omyl, který
   analyzer má chytat; viz `1.0-roslyn-analyzer.md`, sekce Triage.

3. **Otázka odděleného analyzer projektu pro `Pipaslot.Mediator.Http` — vyřešeno, nový projekt není
   potřeba.** Žádné ze zbylých pravidel necílí na typ z `Pipaslot.Mediator.Http` — všechny pracují s typy z
   `Pipaslot.Mediator`: `Pipaslot.Mediator.IMediator` (Dispatch/Execute/DispatchUnhandled/ExecuteUnhandled),
   `Pipaslot.Mediator.Abstractions.IMediatorHandler<TAction>`/`IMediatorHandler<TAction,TResult>`,
   `Pipaslot.Mediator.Authorization.IHandlerAuthorization<TAction>`/`IHandlerAuthorizationAsync<TAction>`/
   `IHandlerAuthorizationMarker` (soubor je pojmenovaný s překlepem `IHanderAuthorizationMarker.cs` —
   samotné rozhraní se jmenuje správně `IHandlerAuthorizationMarker`), `Pipaslot.Mediator.Authorization.IPolicy`.
   Zbylá jednotka jde do existujícího `Pipaslot.Mediator.Analyzers` — žádný nový projekt, žádná nová
   položka v `.slnx`, žádný nový packaging target.

4. **Sdílená analýza pro `PIPMED004` už existuje.** `PIPMED003` zavedl sdílený interní helper
   `HandlerActionTypes.GetHandledActionTypes` (pro danou třídu handleru zjistí množinu obsluhovaných typů
   akcí procházením uzavřených `IMediatorHandler<TAction>`/`IMediatorHandler<TAction,TResult>` v
   `INamedTypeSymbol.AllInterfaces`). `PIPMED004` na něj přímo naváže — stejná procházka `AllInterfaces` se
   nemá psát podruhé.

5. **Rozsah `PIPMED002` v první verzi je záměrně užší než "plný dataflow".** `1.0-roslyn-analyzer.md` označuje
   kandidáta jako "Ano, dataflow" zjistitelné, ale detekovat, že se lokální proměnná s výsledkem *nikdy*
   nepřečte (`.Success`, `.Errors`, ...) později v metodě, je plnohodnotná dataflow analýza s vyšším rizikem
   falešných pozitiv (větvení, early return, uložení do pole/kolekce). V1 cílí jen na **statement-level
   zahození** — `mediator.Dispatch(x);`/`await mediator.Dispatch(x);` jako samostatný `ExpressionStatement`,
   bez přiřazení výsledku kamkoli. Idiomatické potlačení `_ = await mediator.Dispatch(x);` funguje samo od
   sebe — `_ = ...` je `ExpressionStatement` obalující `AssignmentExpressionSyntax`, ne přímo
   `InvocationExpressionSyntax`/`AwaitExpressionSyntax`, takže detekční vzor ho přirozeně nezachytí bez
   zvláštního case. Plné sledování nevyužité proměnné je možné budoucí rozšíření, ne blokující podmínka této
   jednotky.

- **Status:** DONE

  `tests/Pipaslot.Mediator.Analyzers.Tests/IgnoredMediatorResponseAnalyzerTests.cs` (nový),
  `tests/Pipaslot.Mediator.Analyzers.Tests/Pipaslot.Mediator.Analyzers.Tests.csproj` (přidat
  `Microsoft.CodeAnalysis.CSharp.CodeFix.Testing`, verze `5.6.0`-kompatibilní, stejný vzor jako
  `Microsoft.CodeAnalysis.CSharp.Analyzer.Testing`), `docs/wiki/5.-Mediator-API.md` (rozšířit sekci
  `## Execute or Dispatch action with a status response`), `docs/wiki/Release-notes-and-breaking-changes.md`
  (bullet pod `### Roslyn analyzer changes`).
- **Depends on:** žádná
- **Scope:** nové pravidlo detekující zahozenou návratovou hodnotu `IMediator.Dispatch`/`Execute<TResult>`,
  s code fixem.
- **Contents:** Detekce na `SyntaxKind.ExpressionStatement`, jehož `Expression` je (případně přes
  `AwaitExpressionSyntax`) `InvocationExpressionSyntax` rezolvující na `Pipaslot.Mediator.IMediator.Dispatch`
  nebo `Pipaslot.Mediator.IMediator.Execute<TResult>` (ne `DispatchUnhandled`/`ExecuteUnhandled` — ty
  záměrně vyhazují, čtení odpovědi tam nedává smysl). Rozsah v1 viz Analýza #5 — jen statement-level
  zahození, žádný dataflow na proměnné. `_ = await mediator.Dispatch(x);` se přirozeně nezachytí (jiný
  syntaktický tvar), není potřeba speciální case. Code fix nabídne dvě samostatné akce (`CodeAction`):
  (a) obalit `if (!result.Success) { }` kolem statementu s deklarací proměnné pro výsledek, (b) přepsat
  volání na `DispatchUnhandled`/`ExecuteUnhandled`. Zprávy diagnostiky musí explicitně pojmenovat obě
  alternativy (viz `1.0-roslyn-analyzer.md`, odstavec "Ignorovaná odpověď" pod "Detail k P0 pravidlům" pro
  přesné zdůvodnění bug třídy). Wiki: rozšířit
  `5.-Mediator-API.md#execute-or-dispatch-action-with-a-status-response` o odstavec jmenující `PIPMED002`
  a jeho dvě alternativy — nevytvářet novou stránku (viz skill `roslyn-analyzers` sekce Dokumentace).
- **Risk:** mid — první pravidlo s code fixem v tomto projektu, `Microsoft.CodeAnalysis.CSharp.CodeFix.Testing`
  je nový balíček s potenciálně stejnými verzovacími nástrahami jako `Analyzer.Testing` (viz skill,
  sekce Testing) — počítat s dalším laděním `CS1705`/`MSB3277`. Pokud code fix testing zabere
  nepřiměřeně moc času, lze jednotku rozdělit: nejdřív diagnostika bez fixu (samostatný, menší commit),
  code fix jako navazující jednotka — ale zkusit v jednom kroku první.
- **Akceptance:**
  `dotnet build Pipaslot.Mediator.Analyzers/Pipaslot.Mediator.Analyzers.csproj` (0 warnings);
  `dotnet test tests/Pipaslot.Mediator.Analyzers.Tests/Pipaslot.Mediator.Analyzers.Tests.csproj` (nové i
  stávající testy zelené, negativních testů `IgnoredMediatorResponseAnalyzerTests` alespoň tolik co
  pozitivních — pokrýt: `_ = await ...`, přiřazení do proměnné i bez čtení `.Success` později v v1 se
  NEHLÁSÍ [mimo rozsah, ne bug], `DispatchUnhandled`/`ExecuteUnhandled` se nikdy nehlásí, volání mimo
  `ExpressionStatement` např. jako argument jiného volání se nehlásí);

## Nad rámec plánu

- **MediatR interop pravidlo** (`1.0-roslyn-analyzer.md`, "Vzít, pokud tým používá obojí") — podmíněná
  priorita, závisí na tom, jestli konkrétní konzument reálně kombinuje MediatR a Pipaslot.Mediator v jednom
  projektu. Nezahrnuto do tohohle plánu, protože nemá jasného vlastníka/trigger; založit samostatnou jednotku
  až bude konkrétní poptávka.
- **Další kandidáti mimo `1.0-roslyn-analyzer.md`'s triage** (špatný `ServiceLifetime` handleru, chybějící
  handler pro akci, duplicitní handler pro tutéž akci) — vyžadovaly by opt-in přes MSBuild property
  (`CompilerVisibleProperty`/`AnalyzerConfigOptions`) a compilation-end action procházející referencované
  assembly, což je strukturálně jiný a větší tvar pravidla než jednotky výše (žádná z nich nepotřebuje
  opt-in konfiguraci ani `CompilationEndAction`). Zasloužily by si vlastní plán, ne jako další jednotku tady.
- **`Microsoft.CodeAnalysis.PublicApiAnalyzers` přílepek** (`1.0-roslyn-analyzer.md`, sekce Vazby) — CI
  kontrola veřejného API vs. changelog/wiki, nesouvisí s diagnostikami pro konzumenty, jiný účel (interní CI,
  ne balíček pro konzumenta). Samostatné téma.
