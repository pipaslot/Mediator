## Multiple handler execution per single action
From NuGet: **Pipaslot.Mediator** since version **6.0.0**

The mediator has supported multi-handler execution since the early beginning. But the handler definition was changed in version 6. In previous versions, the multi-handler configuration was defined in pipelines. This pipeline configuration was removed in version 6. Now you can apply multiple handlers regardless of pipelines, and they can be specified per action instead of per pipeline.

In the default configuration, only one handler can be defined per action. If you define multiple handlers per action, then `MediatorException` will be thrown. This prevents you from accidentally defining a handler for an incorrect action.

To provide multi-handler execution, you have to implement the interface `ISequenceHandler` or `IConcurrentHandler` in all the handlers for that one action.

**IMPORTANT:** You cannot combine handlers for a single action that implement `ISequenceHandler`, `IConcurrentHandler`, or neither of these two interfaces.

### Sequence handler execution
Allows you to execute one or more handlers one by one by implementing the interface `ISequenceHandler` in all handlers intended to be executed in sequence. Throws a MediatorException if no handler exists for the action. The property `Order` specifies the execution order. Handlers with a lower value have higher priority. If multiple handlers have the same Order, then they are queued randomly. Usage:
```
public class MyAction : IMediatorAction{
}

public class MyActionHandler1 : IMediatorHandler<MyAction>, ISequenceHandler{
   public int Order => 1;
   public Task Handle(MyAction action, CancellationToken cancellationToken){
      Console.WriteLine("Sequence handler 1 was executed as first");
      return Task.CompletedTask;
   }
}

public class MyActionHandler2 : IMediatorHandler<MyAction>, ISequenceHandler{
   public int Order => 2;
   public Task Handle(MyAction action, CancellationToken cancellationToken){
      Console.WriteLine("Sequence handler 2 was executed as second");
      return Task.CompletedTask;
   }
}
```

### Concurrent handler execution
Allows you to execute one or more handlers by implementing the interface `IConcurrentHandler` in all handlers intended to be executed concurrently. Throws a MediatorException if no handler exists for the action. It can be used in cases where you have specific requirements for executing multiple functions, but middleware does not fit your needs. All the handlers are executed simultaneously, but the mediator awaits all of them before providing a response. Usage:
```
public class MyAction : IMediatorAction{
}

public class MyActionHandler1 : IMediatorHandler<MyAction>, IConcurrentHandler{
   public Task Handle(MyAction action, CancellationToken cancellationToken){
      Console.WriteLine("Concurrent handler 1 was executed");
      return Task.CompletedTask;
   }
}

public class MyActionHandler2 : IMediatorHandler<MyAction>, IConcurrentHandler{
   public Task Handle(MyAction action, CancellationToken cancellationToken){
      Console.WriteLine("Concurrent handler 2 was executed");
      return Task.CompletedTask;
   }
}
```

## File download (via HTTP GET) - write custom HTTP response from handlers
From NuGet: **Pipaslot.Mediator.Http** since version **5.0.0**

In previous versions, the mediator supported only HTTP POST requests. This made file download complicated through HTML links/anchors.
[Mediator](2.-Core-concepts-and-glossary.md#mediator) exposes a service `IMediatorUrlFormatter` to make the URL building as easy as possible. This service is registered by configuring the client mediator via `services.AddMediatorClient()`. You only need to inject this service and pass the action instance to get a formatted URL.

```
@inject Pipaslot.Mediator.Http.IMediatorUrlFormatter _mediatorUrlFormatter
<a href="@_mediatorUrlFormatter.FormatHttpGet(new MyFileDownloadAction(FileId))">Download</a>
```

**WARNING:** This approach is not recommended for accessing sensitive files in applications using authentication through request headers (for example, JWT). In the case of links/anchors, the headers are not handed over to the server, which causes a loss of authentication and authorization.

**NOTE:** Keep in mind that the URL query has a limited size depending on your server configuration. We do not recommend sending a large amount of data via the action, like long texts or templates used for file rendering.

### Handler implementation
Once the URL is formatted, you need to expose the file in the HTTP response. If you implement your handler like the following example, the mediator will detect that and won't write its own JSON response.
```
public class MyFileDownloadActionHandler : IMediatorHandler<MyFileDownloadAction>
{
    private readonly IHttpContextAccessor _httpContextAccessor;
    public MyFileDownloadActionHandler(IHttpContextAccessor httpContextAccessor)
    {
        _httpContextAccessor = httpContextAccessor;
    }

    public async Task Handle(MyFileDownloadAction action, CancellationToken cancellationToken)
    {
        var httpContext = _httpContextAccessor.HttpContext;
        if (httpContext == null)
        {
            throw new InvalidOperationException($"Action {nameof(MyFileDownloadAction)} can be used only for request over HTTP.");
        }
        var fileContent = "Hello world!"
        //Without this header, the file download does not pop up in the browser.
        httpContext.Response.Headers["Content-Disposition"] = $"attachment;filename={action.FileName}.txt";
        httpContext.Response.ContentType = "text/plain";
        await httpContext.Response.WriteAsync(fileContent, cancellationToken);
    }
}
```

## Control handler status
There may be specific scenarios when you want to prevent throwing exceptions from the handler because they are captured by error handling middleware and converted into notifications appearing in the UI. You can instruct the mediator to return the unsuccessful status code via IMediatorContextAccessor.
Just 

```
public class MyHandler
{
   private readonly IMediatorContextAccessor _mca;

   public MyHandler(IMediatorContextAccessor mca){
      _mca = mca;
   }

   public async Task Handle(MyAction action, CancellationToken cancellationToken){
      try{
         //Operation causing exceptions in some cases
      }catch(MyException){
         _mca.Context.Status = ExecutionStatus.Failed;
      }
   }
}
```
