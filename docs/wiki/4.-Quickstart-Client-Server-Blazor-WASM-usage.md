Install the NuGet package Pipaslot.Mediator in projects where actions and handlers are placed.
Install the NuGet package Pipaslot.Mediator.Http in projects where the Client and Server DI configuration is placed.

## Shared project
Define the same [action](2.-Core-concepts-and-glossary.md#action) and response contracts as in the [in-process quickstart's Shared project](3.-Quickstart-In-process-usage.md#shared-project) - `WeatherForecastRequest` implementing [`IRequest<TResult>`](2.-Core-concepts-and-glossary.md#request), plus the plain `WeatherForecastResult` response class. The only difference for Client-Server usage is that this project is referenced by both the client and server projects instead of just one executable.

## Server project
Define an action [handler](2.-Core-concepts-and-glossary.md#handler) implementing [`IRequestHandler<TRequest, TResponse>`](2.-Core-concepts-and-glossary.md#request-handler) on your server project:
```
public class WeatherForecastRequestHandler : IRequestHandler<WeatherForecastRequest, WeatherForecastResult[]>
{

    private static readonly string[] Summaries = new[]
    {
        "Freezing", "Bracing", "Chilly", "Cool", "Mild", "Warm", "Balmy", "Hot", "Sweltering", "Scorching"
    };

    public Task<WeatherForecastResult[]> Handle(WeatherForecastRequest request, CancellationToken cancellationToken)
    {
        var rng = new Random();
        var forecast = Enumerable.Range(1, AmountOfDays).Select(index => new WeatherForecast.Result
        {
            Date = request.Since.AddDays(index),
            TemperatureC = rng.Next(-20, 55),
            Summary = Summaries[rng.Next(Summaries.Length)]
        })
        .ToArray();
        return Task.FromResult(forecast);
    }
}
```
Register the mediator, middleware, and the locations of actions and action handlers in your DI:
```
var builder = WebApplication.CreateBuilder(args);
var services = builder.Services;
services.AddHttpContextAccessor(); // May be required by some middleware accessing actual request

// Mediator services
services.AddMediatorServer()
    .AddActionsFromAssemblyOf<WeatherForecastRequest>()
    .AddHandlersFromAssemblyOf<WeatherForecastRequestHandler>();

var app = builder.Build();
app.UseBlazorFrameworkFiles();
app.UseStaticFiles();

// Mediator middleware (register before UseRouting())
app.UseMediator();

app.UseRouting();

app.MapFallbackToFile("index.html");
app.Run();
```

## Client project
Register the mediator service. Usually, you do not need to register actions and handlers on the client if all handlers are placed on the server side only.
Program.cs
```
var builder = WebAssemblyHostBuilder.CreateDefault(args);
builder.RootComponents.Add<App>("#app");
builder.Services.AddScoped(sp => new HttpClient { BaseAddress = new Uri(builder.HostEnvironment.BaseAddress) });

builder.Services.AddMediatorClient();

await builder.Build().RunAsync();
```

and execute on your razor template:
```
@inject IMediator Mediator

@code {
    private WeatherForecastResult[] _forecasts;
    protected override async Task OnInitializedAsync()
    {
        var response = await Mediator.Execute(new WeatherForecastRequest());
        if (response.Success)
        {
            _forecasts = response.Result;
            ...
        }
    }
}
```

Or, if you prefer direct access to the result and the exception in case of an error:
```
@inject IMediator Mediator

@code {
    private WeatherForecastResult[] _forecasts;
    protected override async Task OnInitializedAsync()
    {
        _forecasts = await Mediator.ExecuteUnhandled(new WeatherForecastRequest());
    }

}
```
