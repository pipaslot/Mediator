## Notifications in server response
From NuGet: **Pipaslot.Mediator** since version **4.2.0**

Use this when a handler needs to tell the end user something beyond the result data itself (e.g. "saved successfully" or "quota exceeded") without changing the action's return type. Provides a way to propagate notifications from the server to the client, where they can be handled and presented to the user. A typical example is displaying a warning or successful operation notification after server processing.

### Server
Inject the service `INotificationProvider` where the message should be produced, and use the methods `AddInformation()`, `AddSuccess()`, `AddWarning()` or `AddError()` for attaching to the result collection.

### Client
Register the middleware in your pipeline with `.UseNotificationReceiver()`. Inject the service `INotificationReceiver` where the message should be presented. The component will be notified about a new notification via the event `INotificationReceiver.NotificationReceived`.
```
@implements IDisposable
@inject INotificationReceiver NotificationReceiver
@code {
    protected override void OnInitialized()
    {
        NotificationReceiver.NotificationReceived += OnNotificationReceived;
    }
    public void Dispose()
    {
        NotificationReceiver.NotificationReceived -= OnNotificationReceived;
    }
    private void OnNotificationReceived(object? sender, NotificationReceivedEventArgs args)
    {
        foreach (var notification in args.Notifications)
        {
            // Process new notification
        }
        StateHasChanged();
    }
}
```

## Events
From NuGet: **Pipaslot.Mediator** since version **4.2.0**
Middleware: `ActionEventsMiddleware` with definition `.UseActionEvents()`

Use this when the UI needs to react to actions starting/finishing globally (e.g. a loading spinner), rather than tracking each `Execute`/`Dispatch` call site by hand. 
This mediator exposes two events, `ActionEventsMiddleware.ActionStarted` and `ActionEventsMiddleware.ActionCompleted`, notifying when some action starts processing or ends its processing. 
This can be handy for UI components when you, for example, need to show a spinner if one or more mediator actions are executed.

Arguments for both events contain parameters:

`Action` - Action instance for which the event was published

`RunningActions` - A collection of all actions that are still being processed (except the affected one)

### Simple spinner implementation:
```
@if(_showSpinner){
    <div class="spinner"></div>
}
@implements IDisposable
@inject ActionEventsMiddleware ActionEvents;
@code {
    private bool _showSpinner;

    protected override void OnInitialized()
    {
        ActionEvents.ActionStarted += OnStarted;
        ActionEvents.ActionCompleted += OnFinished;
    }
    public void Dispose()
    {
        ActionEvents.ActionStarted -= OnStarted;
        ActionEvents.ActionCompleted -= OnFinished;
    }

    private void OnStarted(object? sender, ActionStartedEventArgs args)
    {
        if (!_showSpinner)
        {
            _showSpinner = true;
            StateHasChanged();
        }
    }
    private void OnFinished(object? sender, ActionCompletedEventArgs args)
    {
        if (_showSpinner && args.RunningActions.Count == 0)
        {
            _showSpinner = false;
            StateHasChanged();
        }
    }
}
```

## Application Insights integration
Use this when you already rely on Application Insights for telemetry and want mediator action executions to show up there as dependency calls, alongside your other tracked operations. Install the NuGet package **Microsoft.ApplicationInsights.AspNetCore** and configure the instrumentation key. Application Insights exposes a Telemetry client, which can be used for collecting information about action execution. You can use the following example:

```
public class TelemetryMiddleware(TelemetryClient telemetryClient) : IMediatorMiddleware
{
    public async Task Invoke(MediatorContext context, MiddlewareDelegate next)
    {
        using (var operation = telemetryClient.StartOperation<DependencyTelemetry>(context.ActionIdentifier))
        {
            operation.Telemetry.Type = "Mediator";
            operation.Telemetry.Success = true;
            try
            {
                await next(context);
            }
            catch (Exception e)
            {
                operation.Telemetry.Success = false;
                operation.Telemetry.Data = Serialize(context.Action);
            }
        }
    }

    private static string Serialize(object? obj)
    {
        if (obj == null)
        {
            return "NULL";
        }
        try
        {
            return JsonSerializer.Serialize(obj, _serializationOptions);
        }
        catch (Exception e)
        {
            return "Data serialization failed: " + e.Message;
        }
    }
}
```
