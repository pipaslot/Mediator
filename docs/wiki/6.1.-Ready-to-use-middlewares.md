These middlewares can be registered via the full name syntax like `.Use<ExceptionLoggingMiddleware>()`, or you can use shortcuts like `.UseExceptionLogging()` available from NuGet namespaces.

## UseHttpClient (HttpClientExecutionMiddleware)
From NuGet: **Pipaslot.Mediator.Http** since version **4.0.0**

Used as the default handler when configuring MediatorClient.
Forwards actions over HTTP to another server. Requires an HttpClient to be configured. You can configure the HTTP client via the ASP.NET Core HttpClient factory pattern available in your DI.
Usage:
```
// Configure HTTP client for HttpClientExecutionMiddleware
services.AddHttpClient<HttpClientExecutionMiddleware>(client =>
    {
        // Configure HTTP client factory
    })

services.AddMediator()
    ... Configure actions, handlers and pipelines ...
    .UseHttpClient()
    ...
```

## UseExceptionLogging (ExceptionLoggingMiddleware)
From NuGet: **Pipaslot.Mediator.Http** since version **4.0.0**

Logs all exceptions as Errors via the service `ILogger` and provides information about the action type and its parameters. 
OperationCanceledException is logged as a warning only.
Usage:
``` 
services.AddMediator()
    ... Configure actions, handlers and pipelines ...
    .UseExceptionLogging()
    ...
```

## Authorization
From NuGet: **Pipaslot.Mediator** since version **6.2.0**
Middleware: `AuthorizationMiddleware` with the definition `.UseAuthorization()`

Authorize users by policies specified by your application, or use IdentityPolicy, covering basic checks for authentication status, roles, and claims.

## Direct Call Protection
From NuGet: **Pipaslot.Mediator** since version **6.4.0**
Middleware: `DirectCallProtectionMiddleware` with the definition `.UseDirectCallProtection()`

Protects the action from a direct call in the mediator. It allows you to execute the action only as a nested call from another mediator handler or middleware.
The protection is useful for actions hidden behind your demilitarized zone. Let's imagine you use two kinds of queries/actions: the `ApiQuery` and its handler, which has configured middlewares checking authentication, authorization, or different security rules; and the `InternalQuery` and its handler, where these security rules are not applied, but you expect that it will be executed only from the ApiQuery action. The reason for such a configuration can be an increase in throughput by preventing duplicate security policy execution.
In such a case, the `InternalQuery` would have the `DirectCallProtectionMiddleware` middleware configured in the mediator pipeline.

## Direct HTTP Call Protection
From NuGet: **Pipaslot.Mediator.Http** since version **6.4.0**
Middleware: `DirectHttpCallProtectionMiddleware` with the definition `.UseDirectHttpCallProtection()`

It works exactly the same as Direct Call Protection, but in this case, you want to prevent direct calls from the REST API if you are building the Blazor WASM application.
