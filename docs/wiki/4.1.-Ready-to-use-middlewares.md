These middlewares can be registered via the full name syntax like `.Use<ExceptionLoggingMiddleware>()`, or you can use shortcuts like `.UseExceptionLogging()` available from NuGet namespaces.

## Notifications in server response
From NuGet: **Pipaslot.Mediator** since version **4.2.0**

Provides a way to propagate notifications from the server to the client, where they can be handled and presented to the user. A typical example is displaying a warning or successful operation notification after server processing.

### Server
Inject the service `INotificationProvider` where the message should be produced, and use the methods `AddInformation()`, `AddSuccess()`, `AddWarning()` or `AddError()` for attaching to the result collection.

### Client
Register the middleware in your pipeline with `.UseNotificationReceiver()`. Inject the service `INotificationReceiver` where the message should be presented. The component will be notified about a new notification via the event `INotificationReceiver.NotificationReceived`.
```
@implements IDisposable
@inject INotificationReceiver NotificationReceiver
@code {
    protected override void OnInitialized()
    {
        NotificationReceiver.NotificationReceived += OnNotificationReceived;
    }
    public void Dispose()
    {
        NotificationReceiver.NotificationReceived -= OnNotificationReceived;
    }
    private void OnNotificationReceived(object? sender, NotificationReceivedEventArgs args)
    {
        foreach (var notification in args.Notifications)
        {
            // Process new notification
        }
        StateHasChanged();
    }
}
```

## Events
From NuGet: **Pipaslot.Mediator** since version **4.2.0**
Middleware: `ActionEventsMiddleware` with definition `.UseActionEvents()`

This mediator exposes two events, `ActionEventsMiddleware.ActionStarted` and `ActionEventsMiddleware.ActionCompleted`, notifying when some action starts processing or ends its processing. This can be handy for UI components when you, for example, need to show a spinner if one or more mediator actions are executed.
Arguments for both events contain parameters:

`Action` - Action instance for which the event was published

`RunningActions` - A collection of all actions that are still being processed (except the affected one)

### Simple spinner implementation:
```
@if(_showSpinner){
    <div class="spinner"></div>
}
@implements IDisposable
@inject ActionEventsMiddleware ActionEvents;
@code {
    private bool _showSpinner;

    protected override void OnInitialized()
    {
        ActionEvents.ActionStarted += OnStarted;
        ActionEvents.ActionCompleted += OnFinished;
    }
    public void Dispose()
    {
        ActionEvents.ActionStarted -= OnStarted;
        ActionEvents.ActionCompleted -= OnFinished;
    }

    private void OnStarted(object? sender, ActionStartedEventArgs args)
    {
        if (!_showSpinner)
        {
            _showSpinner = true;
            StateHasChanged();
        }
    }
    private void OnFinished(object? sender, ActionCompletedEventArgs args)
    {
        if (_showSpinner && args.RunningActions.Count == 0)
        {
            _showSpinner = false;
            StateHasChanged();
        }
    }
}
```

## Direct Call Protection
From NuGet: **Pipaslot.Mediator** since version **6.4.0**
Middleware: `DirectCallProtectionMiddleware` with the definition `.UseDirectCallProtection()`

Protects the action from a direct call in the mediator. It allows you to execute the action only as a nested call from another mediator handler or middleware.
The protection is useful for actions hidden behind your demilitarized zone. Let's imagine you use two kinds of queries/actions: the `ApiQuery` and its handler, which has configured middlewares checking authentication, authorization, or different security rules; and the `InternalQuery` and its handler, where these security rules are not applied, but you expect that it will be executed only from the ApiQuery action. The reason for such a configuration can be an increase in throughput by preventing duplicate security policy execution.
In such a case, the `InternalQuery` would have the `DirectCallProtectionMiddleware` middleware configured in the mediator pipeline.
